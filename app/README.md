# Север · предыдущая версия на Node.js

Новый сервер, операторские команды и порядок переноса данных описаны в [инструкции Rust + PostgreSQL](../backend/README.md). Эта инструкция относится к версии с SQLite.

Первая рабочая микрофича [KB-AUTH-01](../docs/product/documents/access/kb-auth-01.md) — войти с заранее выданной учётной записью и сохранить сессию при обновлении страницы. Приложение запускается локально на macOS с Node.js 26.

## Запуск

Из корня проекта создайте учётную запись. Команда для zsh запросит пароль от 15 до 128 символов без отображения ввода.

```zsh
IFS= read -rs 'sever_password?Пароль для аккаунта: ' &&
  printf '%s' "$sever_password" | node app/create-account.mjs editor@example.test 'Имя редактора'
unset sever_password
```

Создайте вторую учётную запись с другой почтой для проверки независимого входа. Для скриптов создания пароль также передаётся через стандартный ввод. Для локальной учётной записи используется адрес в ASCII с доменом, разделённым точками. Части домена содержат до 63 символов каждая, весь адрес — до 254, регистр почты не учитывается. Сервер и команда создания используют одну и ту же папку хранилища.

```sh
node app/server.mjs
```

Откройте [форму входа](http://127.0.0.1:4121/) и введите данные созданной учётной записи. После входа обновите [рабочую область](http://127.0.0.1:4121/workspace), чтобы проверить сохранение сессии. Для второго входа и проверки отказа без сессии используйте отдельный профиль браузера или приватное окно. Хранилище находится в закрытой директории `app/.local/`. Для изолированной проверки укажите свою закрытую директорию через `SEVER_DATA_DIR` перед созданием аккаунта и запуском сервера.

## Контракт

| Действие | Результат |
|---|---|
| `GET /` | Форма входа с рабочей почтой и паролем |
| `POST /login` | При совпадении данных сервер устанавливает сеанс и отвечает `303` на `/workspace` или на распознанную исходную ссылку на рабочую область |
| `POST /login` с неподходящими данными | Одинаковый `422` и подсказка «Неверная почта или пароль.» для разных причин отказа |
| `POST /login` сверх лимита | `429` с `Retry-After` и повторной формой |
| `GET /workspace` | Каталог текущей среды. С отсутствующей или истёкшей сессией переадресация на форму входа |

Сервер слушает `127.0.0.1:4121` и принимает форму по тому же origin. SQLite хранит почты, имена, хеши паролей с индивидуальной солью scrypt и хеши случайных идентификаторов сессий. Для браузерной сессии срок составляет 12 часов. Cookie привязана к хосту и пути `/workspace` с `HttpOnly` и `SameSite=Strict`. Журнал содержит исход входа и непрозрачный идентификатор при успехе. Режим рассчитан на локальный HTTP. Для публикации потребуется отдельная конфигурация HTTPS и актуальной политики сессий. [Рекомендации OWASP по паролям](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) · [Сессии](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)

```sh
node --test app/auth.test.mjs
```

## Проверка создания закрытого пространства

Для KB-SPC-01 подготовьте отдельную папку данных с учётными записями. Запуск сервера и штатное создание аккаунта сохраняют схему 1. Явная команда `configure-tenants.mjs` дополняет указанную схему до версии 2 вместе с установкой членств. Существующие аккаунты и сессии сохраняются. Закреплённый выпуск KB-AUTH-01 открывает схему 1, поэтому для проверки используйте копию исходной базы или пустую тестовую папку.

После создания аккаунтов через `create-account.mjs` подготовьте файл `tenants.json`. Укажите неизменяемые UUID тенантов и почты уже существующих учётных записей.

```json
{
  "tenants": [{"id": "a36ef841-c7f2-4df3-8fde-93dd23d54cca", "name": "Студия «Контур»"}],
  "memberships": [
    {"tenantId": "a36ef841-c7f2-4df3-8fde-93dd23d54cca", "email": "creator@example.test", "role": "member", "status": "active", "canCreate": true, "current": true},
    {"tenantId": "a36ef841-c7f2-4df3-8fde-93dd23d54cca", "email": "admin@example.test", "role": "admin", "status": "active", "canCreate": false, "current": true}
  ]
}
```

`current: true` выбирает среду для `/workspace`. У аккаунта может быть несколько членств и одна текущая среда. Поддерживаемые роли — `member`, `admin`, `superadmin`. Статус `inactive` отключает доступ этого членства. Повтор команды с тем же файлом сохраняет те же настройки.

```sh
export SEVER_DATA_DIR="/путь/к/изолированной/базе"
node app/configure-tenants.mjs tenants.json
node --input-type=module -e 'import {createSeverServer} from "./app/server.mjs"; const server = createSeverServer(); server.listen(0, "127.0.0.1", () => console.log(`http://127.0.0.1:${server.address().port}/`))'
```

Запустите тестовый сервер после подготовки тенантов. Если он уже работал на схеме 1, перезапустите его. В браузере откройте напечатанный адрес. Вход создателя показывает действие «Создать пространство». Администратор той же среды может открыть сохранённую ссылку. [HTTP-контракт](../docs/product/first-microfeature/sa.md) · [Матрица проверок](../docs/product/first-microfeature/checks.md)

```sh
node --test app/*.test.mjs feature-center/*.test.mjs
```

## Каталог, переключатель и назначения пространств

После входа `/workspace` показывает каталог текущего тенанта. Левый переключатель открывает каталог другого доступного тенанта. Каталог и шапка «Документов» используют один серверный список пространств текущего тенанта. При переходах по строкам каталога и возврате сохраняются `q`, `scope` и `page`. Доступ проверяется при каждом запросе, в том числе после входа по прямой ссылке.

Для прямых назначений на существующие закрытые пространства подготовьте JSON. UUID пространства берётся из его постоянного адреса, а почта принадлежит действующему участнику того же тенанта.

```json
{
  "grants": [
    {"tenantId": "a36ef841-c7f2-4df3-8fde-93dd23d54cca", "spaceId": "c48a61fb-074c-4ef5-bec6-3d821daf8f40", "email": "editor@example.test", "role": "editor"}
  ]
}
```

```sh
SEVER_DATA_DIR="/путь/к/изолированной/базе" node app/configure-space-grants.mjs space-grants.json
```

Роли `viewer` и `editor` дают просмотр пространства. Значение `null` отзывает прямое назначение. Команда применяет только перечисленные назначения. Повторная отправка файла сохраняет тот же результат. Файл `{"grants":[]}` выполняет только миграцию со схемы 2 на 3. Миграция и изменения выполняются вместе. Если любая строка не проходит проверку, команда откатывает весь набор. При деактивации членства или отзыве назначение перестаёт давать доступ со следующего запроса.

Схема 2 открывается в режиме владельца и администратора. Перед миграцией действующего хранилища подготовьте согласованную резервную копию SQLite со всеми записями журнала и проверьте её восстановление. Версия, запущенная до миграции, открывает схему 2. [Системная спецификация](../docs/product/documents/spaces/kb-spc-02-sa.md) · [План проверок](../docs/product/documents/spaces/kb-spc-02-checks.md)

## Самостоятельная регистрация по почте

`SEVER_SELF_REGISTRATION=true` добавляет ссылку «Зарегистрироваться» к форме входа. Для выключения установите `SEVER_SELF_REGISTRATION=false` или удалите переменную и перезапустите сервер. Самостоятельная регистрация по умолчанию выключена. При любом значении флага можно войти в существующий аккаунт и выдать новый через `app/create-account.mjs`.

Для включения подготовьте схему тенантов и настройте локальную доставку. Укажите абсолютный путь к sendmail-совместимому исполняемому файлу, который принимает письмо через stdin с аргументами `-i -t`, и адрес отправителя. Сервер проверит конфигурацию на старте. Доставку писем обеспечивает выбранная и настроенная почтовая служба.

Запустите эти команды из корня проекта, чтобы создать отдельное хранилище и открыть сервер на свободном локальном порту.

```sh
sever_registration_dir=$(mktemp -d)
export SEVER_DATA_DIR="$sever_registration_dir"
printf '%s\n' '{"tenants":[],"memberships":[]}' > "$sever_registration_dir/tenants.json"
node app/configure-tenants.mjs "$sever_registration_dir/tenants.json"
export SEVER_SELF_REGISTRATION=true
export SEVER_REGISTRATION_SENDMAIL=/usr/sbin/sendmail
export SEVER_REGISTRATION_FROM=noreply@example.org
node --input-type=module -e 'import {createSeverServer} from "./app/server.mjs"; const server = createSeverServer(); server.listen(0, "127.0.0.1", () => console.log(`http://127.0.0.1:${server.address().port}/`))'
```

Подставьте путь к настроенному sendmail и действительный адрес отправителя. Откройте напечатанный URL, запросите ссылку на свою почту, затем откройте письмо в браузере на компьютере, где запущен сервер. Ссылка использует адрес `http://127.0.0.1` и порт этого запуска, поэтому на другом компьютере обратиться к серверу через неё нельзя.

После подтверждения укажите имя и пароль. Приложение откроет «Мою среду» с правом создавать пространства. Ссылка действует 30 минут и перестаёт действовать после создания аккаунта. После перезапуска запросите новую ссылку. Повторная отправка на тот же адрес доступна через минуту.
