# Агентский процесс разработки

Проектируем полноценную рабочую среду для людей и AI-агентов. Текущие макеты исследуют интерфейс. Разработку ведём микрофичами с наблюдаемым результатом и приёмкой на рабочей версии. Первая область проработки — документы и пространства.

Запуск доски и работа с реестром описаны в [инструкции центра фич](feature-center/README.md).

Интерфейс «Севера» написан на React и TypeScript. Сервер на Rust работает с PostgreSQL. [Docker-стенд](backend/README.md#docker-стенд) · [Сборка и перенос данных из SQLite](backend/README.md)

Подтверждённое владельцем правило: требования, макеты, старт реализации и релиз согласует владелец продукта; технические переходы и раунды исправлений внутри разрешённой задачи ведёт оркестратор.

## Что уже определено

- Одна микрофича даёт один проверяемый пользовательский или операторский результат. Готовность подтверждается по согласованным критериям на фиксированной рабочей версии.
- Три маршрута: новая фича, описанная фича, сообщение об ошибке.
- Оркестратор совмещает координацию и ведение продукта; при росте объёма продуктовую работу можно делегировать отдельной роли.
- Разработчики пишут поведенческие тесты до соответствующей реализации, небольшими срезами.
- Каждый независимый QA-проход получает новый контекст и проверяет фиксированную версию.
- Закрытие QA требует пустого списка открытых ошибок в согласованной области и выполненных обязательных проверок.
- Для текущего механизма исполнения доступно четыре одновременных агента, включая оркестратора; расписание учитывает этот предел.
