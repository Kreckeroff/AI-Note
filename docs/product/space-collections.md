# Реестры пространства 1.0

Владелец 21 ноября делегировал продуктовые решения и старт. Участник открывает «Реестры» с доски задач текущего пространства. Каждая строка реестра имеет постоянный адрес карточки. Типичный сценарий — каталог интеграций с датой проверки, ответственным, стоимостью и признаком готовности. [Карта возможностей](notion-workspace-audit.md)

| Сценарий | Проверяемое поведение |
| --- | --- |
| Доступ | Каталог, таблица и карточка доступны по праву просмотра пространства. Владелец и участник с выданной пространственной ролью редактора меняют записи и структуру. Именованное приглашение только на документ сохраняет границы этой страницы. |
| Создание | Реестр получает название до 100 символов. Первый столбец «Название» входит в схему по умолчанию. Названия реестров внутри пространства и названия полей в одном реестре уникальны без учёта регистра. Название записи может повторяться. Повторная отправка одного создания приносит прежний результат. |
| Поля | Редактор добавляет до 32 полей. Допустимы текст до 1000 символов, число, календарная дата или флажок. Название записи обязательно. У существующих записей новое поле пусто, флажок снят. |
| Таблица и карточка | Таблица показывает названия, типы свойств и 50 записей на странице. Каждая строка открывает ссылку на карточку. Текстовые значения экранируются. У широкой таблицы своя горизонтальная прокрутка. |
| Сохранение | Сервер проверяет право, типы, версию структуры и версию записи. При столкновении двух редакций второй автор видит предупреждение, свой ввод и ссылку на сохранённую версию. Перезапись требует повторного явного действия. |

Отдельные пути и составные внешние ключи связывают реестр, поля и записи с тенантом и пространством. Изменение существующей схемы задач не требуется. Формы используют POST с проверкой источника, адреса чтения работают при выключенном JavaScript. Исходная таблица реестра и поля относятся к пространству, экспорт, агрегаты и календарь относятся к последующим версиям.

Два теста Rust проверяют типы, сохранение в PostgreSQL 16, идемпотентное создание, конкурентную запись и отзыв доступа. В Chrome при отключённом JavaScript проверены создание через «Задачи → Реестры», четыре типа полей, изменение карточки, повторное открытие, конфликт двух вкладок и чтение на 320 и 390 px. Проверочный стенд использует отдельную синтетическую базу.
