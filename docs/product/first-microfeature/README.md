# KB-SPC-01 · Пакет проработки

Подготовка следующего шага после локального входа. Микрофича позволяет создать закрытое пространство и открыть его как владелец после повторного входа. [История](../documents/spaces/kb-spc-01.md) · [Техническая SA](sa.md) · [Локальный вход](../documents/access/kb-auth-01.md)

## Цель и границы

Пользователь с правом создания вводит название и получает закрытое пустое пространство, в котором он владелец. После повторного входа он открывает пространство по сохранённой ссылке. Администратор организации открывает её закрытое пространство по роли. Обычный участник без права просмотра получает отказ. Для первого организационного сценария предлагается проверять создание с предвыданным правом. Управление этим правом, каталог, организационный обзор доступа, приглашения и разделы поставляются отдельными микрофичами.

## Что показать на макете

- На стартовом экране пользователя с правом создания кнопка «Создать пространство» открывает диалог «Новое пространство». Поле «Название» получает фокус. «Создать» показывает ожидание во время записи. При ошибке название остаётся в форме. Название из пробелов, название длиннее 100 символов и совпадение названия у текущего владельца требуют исправления.
- После успеха заголовок пустой области показывает введённое имя. У владельца есть устойчивый адрес. После обновления остаются имя и пустое состояние. На узком экране форма и состояния помещаются в одну колонку.
- У участника организации без права создания действие скрыто. При открытии прямой ссылки обычным участником без права просмотра сообщение об отказе не раскрывает название.

## Решения владельца

- В режиме организации администратор выдаёт участникам право создавать пространства. В установке без организации создать пространство может любой вошедший пользователь.
- После обрезки крайних пробелов название содержит 1–100 символов и уникально среди пространств одного владельца.
- Для работы примерно со 100 пространствами нужен отдельный экран каталога. Администратор видит все пространства своей организации и может открыть содержимое каждого по роли, включая закрытые пространства. [Пример каталога пространств в Confluence](https://support.atlassian.com/confluence-cloud/docs/navigate-spaces/)
- Права просмотра и редактирования пространства различаются. Администратору нужен один экран со списком людей и их правами по всем пространствам организации. [KB-ACL-20](../documents/sharing/kb-acl-20.md)

## Порядок поставки

1. [KB-SPC-01 «Создать закрытое пространство»](../documents/spaces/kb-spc-01.md) проверяет право создания и открывает пустую область с названием и постоянным адресом. Владелец открывает её повторно. Для проверки организационного сценария право создания выдаётся заранее. Администратор своей организации открывает область по роли, участник без просмотра получает отказ.
2. Для [KB-SPC-02](../documents/spaces/kb-spc-02.md) предлагается отдельный каталог «Пространства» в основной навигации. Обычный участник видит и открывает пространства с правом просмотра. Администратор видит и открывает все пространства своей организации. Предложение для каталога включает поиск по части названия без учёта регистра и фильтры «Все доступные», «Мои» и «По членству» для участника. В пустом каталоге действие «Создать пространство» появляется у пользователя с этим правом. При отсутствии совпадений можно очистить поиск. На наборе около 100 записей проверяется, что поиск охватывает весь доступный каталог и соблюдает границы организации и прав.
3. [KB-AUTH-17](../documents/access/kb-auth-17.md) даёт администратору выдать и отозвать право создания у действующего аккаунта.
4. Доступ к конкретному пространству назначается при приглашении в [KB-ACL-01](../documents/sharing/kb-acl-01.md). [KB-ACL-02](../documents/sharing/kb-acl-02.md) показывает людей и их роли, [KB-ACL-03](../documents/sharing/kb-acl-03.md) меняет права просмотра и редактирования, [KB-ACL-04](../documents/sharing/kb-acl-04.md) отзывает членство.
5. [KB-ACL-20](../documents/sharing/kb-acl-20.md) даёт администратору один экран со всеми пространствами своей организации и людьми с действующими правами просмотра и редактирования по каждому пространству.

## Предложение для приёмки организационного обзора

- Администратор на одном экране находит любое из примерно 100 пространств своей организации, включая закрытое, и видит, кто может просматривать и редактировать его содержимое. Один поиск охватывает полный набор пространств и людей, доступный в обзоре.
- Права отображаются по действующим разрешениям. После изменения роли или отзыва членства обновлённый обзор отражает новый доступ. Право администратора на чтение действует по роли. Право редактирования отображается при наличии отдельного основания.
- Обычный участник не открывает организационный обзор. Организационный обзор, каталог и открытие содержимого ограничены границами организации и правами аккаунта.

Версия интерфейса и правила сравнения названий сверяются с владельцем перед стартом.
