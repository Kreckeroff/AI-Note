# KB-SPC-01 · Создать закрытое пространство

Черновик · Базовый контур · [Пространства](README.md)

## История

**Пользователь с правом создания** хочет начать собирать материалы команды в отдельной рабочей области. Он вводит название и становится владельцем созданного пространства.

## Решения владельца

- В режиме организации закрытое пространство может создать вошедший участник, которому администратор выдал право создания. В установке без организации право есть у любого вошедшего пользователя.
- Название содержит от 1 до 100 символов после обрезки крайних пробелов. У одного владельца названия уникальны. Разные владельцы могут выбрать одинаковое название.
- Администратор организации видит все её пространства и открывает содержимое каждого пространства по роли, в том числе закрытого.
- Для работы примерно со 100 пространствами нужен отдельный экран каталога. Просмотр и редактирование содержимого задаются отдельными правами. Администратору нужен единый обзор людей с этими правами по всем пространствам своей организации. [Границы и порядок поставки](../../first-microfeature/README.md#порядок-поставки) · [KB-ACL-20](../sharing/kb-acl-20.md)

## Приёмка

- **К1.** Пользователь с правом создания отправляет форму. Открывается пустая область с сохранённым названием. После повторного входа владелец открывает её по тому же адресу.
- **К2.** Участник организации без права создания не видит действие «Создать пространство» и получает отказ при прямой отправке. Без действующей сессии создание недоступно.
- **К3.** Администратор организации открывает её закрытое пространство по прямой ссылке без членства в нём. Обычный участник без права просмотра получает отказ без раскрытия названия.
- **К4.** Название из пробелов, название длиннее 100 символов и повтор названия у того же владельца дают ошибку в форме с сохранением ввода. Другой пользователь с правом создания может выбрать то же название.
