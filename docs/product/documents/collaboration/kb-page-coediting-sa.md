# Совместное редактирование страниц 1.0 · пакет на старт

[Согласованные требования и макет 1.0](kb-page-coediting-1.0.md) · [Регламент](../../../workflow/operating-model.md)

Пакет объединяет KB-COL-07, KB-COL-08 и KB-COL-09 на одном зафиксированном кандидате. Перед изменениями проверяем интеграцию с опубликованным срезом шеринга и комментариев. [Срез 4d645eead8f8 в main](https://github.com/Kreckeroff/AI-Note/commit/2ac345845859eb27def458e7a73b46091cf49659)

## Сервер и данные

Rust проверяет действующую сессию и эффективные права страницы. Используем текущую область `tenant / space / page / account`. Чтение допускает к именованному присутствию и подписке. Редактирование допускает к общему черновику, отправке правок и публикации. Адресный гость подчиняется тем же правилам. Публичный маршрут обслуживает опубликованный снимок.

- PostgreSQL хранит один подтверждённый общий Markdown-черновик страницы, порядковый номер изменений, базовую опубликованную редакцию и журнал подтверждённых операций для восстановления сеанса. Текущая публикация, история, обложки, вложения и ссылки комментариев продолжают использовать свои сущности. Новая таблица черновиков заполняется при первом входе редактора из текущей публикации. Снапшот старой страницы при миграции сохраняется целиком.
- Изменяющие операции, проверка прав и публикация сериализуются по странице под существующим порядком блокировок. Операция содержит UUID, версию черновика, диапазон и текст вставки. Сервер сохраняет отпечаток команды и итог с автором. Повтор того же UUID и данных возвращает записанный итог. Другая команда с тем же UUID возвращает конфликт.
- Диапазоны задаём в Unicode-символах с однозначным преобразованием из позиции редактора. Сохраняем исходные символы Markdown вне правки. Непересекающиеся операции переносим относительно уже подтверждённых. Вставки в один разрыв сохраняем обе в порядке серверного подтверждения. Если две замены задевают один фрагмент и их нельзя применить однозначно, сервер возвращает версии этого фрагмента для совмещения. Остальные подтверждённые правки сохраняются. Ручное совмещение проверяет актуальную версию перед применением.
- React обновляет текущий редактор подтверждёнными операциями, сохраняет выделение и держит свою очередь в памяти открытой вкладки. Визуальный редактор и исходник отправляют операции одного черновика. Undo строит обратную операцию только для своего изменения. Если коллега уже изменил затронутый текст, действие проходит ту же проверку пересечения. Динамическое обновление откладывается до завершения текущего ввода через IME.
- На период редактирования сервер выдаёт идентификатор допуска к странице и связывает его с сессией и версиями прав. Обновление или отзыв основания инвалидирует старый допуск. Сохранённое право проверяется снова, а клиент получает актуальный снимок перед повторным применением очереди. Операция со старым допуском после отзыва или повторной выдачи требует подтверждения новой сессии и не переигрывается автоматически.
- Присутствие хранит активные вкладки с коротким сроком. Сводка по аккаунту выбирает доступный режим «редактирует» при наличии хотя бы одной такой вкладки. При закрытии используется событие завершения. Если клиент пропал, запись исчезает по тайм-ауту до 15 секунд. Во время выдачи сводки проверяются текущие права участников. Присутствие можно восстановить после рестарта приложения, подтверждённый черновик и операции остаются в PostgreSQL.

## Границы интерфейсов

Предлагаем обычные команды по HTTPS и поток событий с восстановлением по номеру изменения. Во всех запросах используется существующая cookie и проверка источника для изменений состояния. При изменении прав сервер закрывает устаревшие потоки. Читатель обновляет опубликованный снимок при поступлении номера новой редакции. Клиент перепроверяет права при повторном подключении и получает пропуски от последнего подтверждённого номера. Если пропуск уже вне окна журнала, клиент получает актуальный снимок и совмещает очередь до отправки или оставляет её в ручном разборе.

| Поверхность | Контракт |
|---|---|
| Открыть редактор | Сервер возвращает актуальный черновик, его номер, опубликованную редакцию и допуск текущего аккаунта. Запрос чтения возвращает только публикацию. |
| Применить правку | Клиент отправляет номер снимка, UUID операции и замену фрагмента. Сервер возвращает подтверждённый номер и операцию либо конфликт фрагмента. Читатель с действующим правом просмотра получает явный отказ на запись. При отсутствии чтения ответ скрывает данные страницы. |
| События | Редактор получает подтверждённые изменения и публикацию. Читатель получает доступную сводку присутствия и номер новой публикации. Черновой текст и его изменения доступны по праву редактирования. Событие отзыва завершает выдачу для утратившего право клиента. |
| Сохранить | Ожидаемый номер общего черновика, идентификатор операции и локальные изменения медиа текущего автора. В одной транзакции проверяем актуальность, применяем ранее существующее сохранение с файлами и создаём одну опубликованную редакцию. При расхождении возвращаем новый снимок для проверки. Повтор и отсутствие изменений сохраняют номер истории. |
| Локальное медиа | Черновые файлы и обложка подготовлены через действующие маршруты автора. Ссылку на такой файл держим в его локальной части до атомарной публикации файла и текста. В общем черновике используем уже опубликованные вложения. При правке другого редактора локальная часть остаётся у автора и при пересечении проходит совмещение. |
| История и прежняя форма | Открытие, сравнение и восстановление используют опубликованные редакции. Восстановление сохраняет общий черновик и обновляет его базу. Если задет тот же фрагмент, показывается совмещение. Обычная форма сохранения подключается к той же проверке версий и сохраняет ввод при конфликте. |
| Следить | Один переключатель по паре аккаунт и страница, повтор сохраняет состояние. При публикации вычисляем текущих подписчиков с правом чтения. Уникальное событие связано с подписчиком и созданной редакцией, автор публикации исключён. Отписка и отзыв проверяются в порядке фиксации с публикацией. Колокольчик применяет текущее право чтения при выдаче, обычный адрес проверяет то же право при переходе. |

Сбой записи не удаляет введённое. В ожидании сети или решения пересечения кнопка «Сохранить» в этом сеансе показывает причину недоступности. Редактор с актуальным подтверждённым снимком может опубликовать общий текст. Другой сеанс позже синхронизирует свою очередь для следующей публикации. «Вернуться к чтению» оставляет подтверждённый черновик у команды. При несинхронизированном вводе показываем предупреждение перед выходом.

## Срезы разработки

1. **Присутствие.** Добавить состояние вкладки и права на сводку, реализовать ряд аватаров и клавиатурный список. Проверить закрытие, другую страницу, гостя и отзыв.
2. **Общий черновик.** Согласовать модель операций для Rust и React. Проверить две вставки, Undo, восстановление очереди, пересечение и отозванный допуск. Вести интеграцию редактора и серверные операции параллельно.
3. **Публикация и история.** Подключить подтверждённый снимок к действующему сохранению с Markdown и медиа. Проверить опубликованное чтение, историю, восстановление и сохранение через прежнюю форму.
4. **Подписка.** Использовать тот же момент создания редакции для уведомления. Добавить действие в контексте страницы и запись в существующий колокольчик. Собрать один кандидат.

## Проверки кандидата

| Область | Обязательные случаи |
|---|---|
| Присутствие | Один аккаунт в двух вкладках, два аккаунта, гость, публичный URL, другая страница и другой тенант. Закрытие редакторской вкладки, аварийный тайм-аут, смена роли, отзыв и повторная выдача. Аватары, `+N` и клавиатурная доступность на широком и узком экранах. |
| Сходимость | Одновременные вставки в одном и разных местах на двух независимых клиентах. Разные порядки доставки, повторы, составной Unicode, смена режима и Undo на фоне чужой правки. Пересечение и повторный конфликт во время совмещения. |
| Соединение и доступ | Ожидающие операции в открытой вкладке, восстановление связи, повтор одного пакета, разрыв перед подтверждением, повтор после рестарта. Отзыв во время записи, отзыв и повторная выдача пока клиент отключён. Нейтральный отказ после полной потери чтения. |
| Публикация | Читатель и публичный URL до и после «Сохранить». Две конкурирующие публикации и повтор. Вложения автора до публикации, обложка, архив, комментарии к фрагменту и сохранение через прежнюю форму. Восстановление редакции при активном общем черновике. |
| Подписка | Один аккаунт в двух вкладках, чужая и своя публикации, повтор, сохранение без изменений, восстановление, отписка и гонка с публикацией. После отзыва события и обычный адрес закрыты. После восстановления доступа события за пропущенный период отсутствуют. |
| Регрессия и показ | Сборка React, Rust и PostgreSQL, проверки редактора и шеринга. На копии Docker-базы сверяем старые страницы, редакции и файлы. Независимый QA выполняет общий проход, после проверки тот же кандидат показывается на 4125. |
