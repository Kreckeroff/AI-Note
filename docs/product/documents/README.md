## С чего начать

**Первый рабочий шаг — локальный вход с заранее выданным аккаунтом.** Он даёт серверную сессию и позволяет проверить закрытое пространство разными аккаунтами. Следующая предметная микрофича даёт владельцу создать закрытое пространство и открыть его повторно. Сторонний аккаунт получает отказ. [KB-AUTH-01](access/kb-auth-01.md) · [KB-SPC-01](spaces/kb-spc-01.md) · [Пакет создания пространства](../first-microfeature/README.md)

Дальше наращиваем базовый контур по одной принятой возможности. Пространство и раздел → страница и сохранение текста → приглашение и управление доступом → поиск по доступным материалам. Markdown-форматирование, редакции и экспорт добавляются отдельными микрофичами по мере готовности предпосылок. Публичные ссылки, SSO, расширения и миграции ведутся отдельными карточками.

Статусы и очередь исполнения ведутся на [доске](http://127.0.0.1:4117/#backlog). Базовый контур отмечает предлагаемые предпосылки ежедневной работы. Порядок после первой микрофичи уточняем по зависимостям и результатам проверок.

## Решения по границам

- Одно пространство содержит разделы и страницы. Дочерние страницы и вложенные разделы имеют отдельные карточки. Связь проекта с разделом понадобится при интеграции с задачами.
- Базовый доступ строится вокруг закрытого пространства, участников и доступа к конкретному материалу. Наследование, пересечение нескольких оснований и публичный просмотр прорабатываются в соответствующих карточках.
- Редактирование без аккаунта остаётся открытым продуктовым решением. Карточка публичной ссылки описывает сценарий просмотра.
- Поддержка Markdown описывается по отдельным конструкциям. Для каждой определяем исходник, ввод, чтение и сохранение. Форматы обмена и расширения имеют собственный цикл.
- При проектировании первой микрофичи интерфейс сверяется с [визуальной основой](../visual-style.md). Компоненты и состояния добавляются по мере прохода реального действия. Предпочтения пользователя, клавиатура и адаптивность отслеживаются как отдельные возможности.
