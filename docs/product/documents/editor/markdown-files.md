# Перенос страницы через Markdown · 1.0

21 ноября 2026 года. Владелец поручил самостоятельно выбирать и реализовывать доработки по результатам сравнения с Notion. Для этого пакета выбраны перенос опубликованного текста и замена текста открытого черновика с предварительным просмотром.

В Notion можно импортировать текстовые и Markdown-файлы и экспортировать страницу с дочерними материалами. В «Севере» единицей переноса в этой версии служит текст одной страницы. Создание новой страницы прямо из файла в выбранном разделе остаётся отдельным сценарием. ## Сценарии и критерии

| Действие | Проверяемый результат |
| --- | --- |
| Вошедший читатель нажимает «Скачать Markdown» под вложениями | Браузер скачивает один файл с названием страницы и расширением `.md`. Файл содержит точный сохранённый исходник текущей публикации, включая экранирование старых текстовых страниц, пробелы и переводы строк. На открытой странице кнопка работает повторно. |
| Пользователь лишился права чтения после открытия страницы | Каждый запрос скачивания проходит обычную проверку доступа к выбранным странице, пространству и организации. После отзыва сервер закрывает доступ к содержимому. Анонимная публичная страница использует собственный маршрут. |
| Редактор выбирает «Импорт Markdown» под вложениями | Диалог принимает один файл `.md` или `.markdown` в UTF-8 объёмом до 60 000 символов. Видны исходник из файла и возможность сверить текущий текст. Неверное расширение, двоичные данные, ошибка чтения и превышение лимита оставляют черновик доступным. |
| Редактор применяет импорт в непустую страницу | Кнопка «Заменить текст черновика» явно подтверждает замену всего текста. Нулевой размер файла даёт пустой текст. Выбор файла и «Отменить» сохраняют текущее содержимое. Служебная метка UTF-8 в начале файла снимается, окончания строк приводятся к LF. |
| Во время просмотра файла пришла правка другого редактора | В диалоге виден обновлённый текст. Для замены требуется ещё раз подтвердить актуальную версию. Смена страницы закрывает диалог и прекращает работу по его запросам. |
| Редактор завершает импорт | Действие входит в обычную историю Undo/Redo и общий черновик. Название, обложка и набор вложений сохраняются. Публикация через штатное сохранение создаёт редакцию по тем же правилам, что обычная правка. |

## Границы переноса

В файл входят Markdown-ссылки на документы, вложения и внешние блоки в том виде, в котором их сохранил автор. Двоичные данные вложений, обложка, обсуждения, адресные права и история остаются в «Севере». Для открытия внутренних ссылок потребуется доступ к исходному материалу. При переносе между страницами внутренние изображения и файлы при необходимости прикрепляют заново.

В версии 1.0 разрешение на экспорт опубликованного текста следует действующему праву чтения именованного пользователя. Отдельная политика отключения экспорта для организации потребует настройки в модели доступа.

## Реализация и проверка

Скачивание использует обычный GET страницы с параметром `download=markdown`. Rust получает опубликованный исходник после серверной проверки доступа и передаёт его как UTF-8 с заголовком загрузки. При импорте чтение файла и предпросмотр происходят в браузере. Подтверждение проходит через ту же операцию редактирования, синхронизации и истории, что и ввод текста.

В Chrome проверены ошибка файла, предпросмотр, отмена, защита от случайной публикации сочетанием клавиш, замена и Undo/Redo при ширине 320 и 1360 px. При 390 px проверены пустой файл и изменение черновика коллегой до подтверждения. Для этих проверок использован рабочий клиент с тестовыми ответами совместной сессии. Клиентские тесты охватывают UTF-8, повреждённые данные, ограничения размера и пробельные символы. Серверные проверки охватывают отдачу сохранённого исходника и повторную проверку права после отзыва.
