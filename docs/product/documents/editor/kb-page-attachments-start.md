## Сценарий и правила

В редакторе под текстом виден блок «Вложения» с именами файлов, размерами и доступными действиями. «Прикрепить файл» добавляет файл в черновик. Команда «Изображение» в меню `/` предлагает выбрать картинку из вложений или загрузить новую. В списке вложений у картинки есть то же действие «Вставить в текст». Для каждой вставки редактор задаёт описание или явно отмечает её декоративной. Одна картинка может быть вставлена несколько раз с разными описаниями.

Общее «Сохранить» публикует текст, обложку и вложения вместе. Сохранение только вложений тоже создаёт редакцию. При чтении опубликованные файлы перечислены под текстом. Действие «Скачать» доступно по действующему праву чтения страницы. Скопированный адрес открывается с той же проверкой. Права получателей, приглашённых напрямую на документ, добавляются вместе с [KB-ACL-06](../sharing/kb-acl-06.md).

Удаление картинки из текста оставляет её во вложениях. Если у файла есть вставки, удаление из списка показывает их число и после подтверждения убирает их из черновика. Файл без вставок удаляется из черновика сразу, как в макете. При отмене всего черновика сохраняется опубликованная страница. После сохранения удаления текущий адрес файла закрывается. Редактор с действующим правом правки может открыть файл по отдельному адресу прежней редакции. Восстановление редакции возвращает файл вместе с текстом и обложкой, а файл получает новый текущий адрес.

Пределы 1.0 — 20 МБ на файл, 20 файлов и 100 МБ суммарно на странице. Поддерживаем PDF, TXT, Markdown, DOCX, XLSX, PPTX, PNG, JPEG и WebP. В текст вставляются PNG, JPEG и WebP. Для внешних изображений и обоих способов вставки видео предусмотрены [KB-FIL-05–07](../media/README.md).

## Макет и состояния

Макет использует дерево, шапку и цвета исходного рабочего пространства. Список остаётся сразу под текстом в режимах чтения и правки. Имя переносится на узком экране, кнопки переходят на следующую строку. Модальная форма использует ширину до 520 px и оставляет скролл внутри. Escape закрывает форму, возвращает фокус и сохраняет черновик. После вставки фокус возвращается в текст. Загрузка использует статус, ошибки видны рядом с выбранным файлом. Действие сохранения ждёт незавершённые загрузки; при ошибке загрузки редактор может повторить её или убрать неудавшийся файл из черновика.

В макете можно выбрать образец картинки, заполнить описание, сохранить страницу и проверить вкладку «Режим читателя». Кнопка «Прикрепить файл» использует локальный выбор файла в браузере. Макет хранит демонстрационные изменения до обновления вкладки. [Пустой список](http://127.0.0.1:4120/design/sever-prototype/kb-fil-01.html?view=empty)

## Техническое решение

- React использует общий список файлов для чтения и правки, команды меню `/` и буфер текущего редактора. Отмена диалога сохраняет выделение. В исходнике остаётся стабильная ссылка `![описание](attachment:<id>)`. Оба режима и серверное чтение разрешают её только по набору файлов страницы, черновика или конкретного снимка. Markdown из прежних страниц сохраняет прежнее поведение для внешних и неподдерживаемых адресов.
- Axum принимает ограниченные по размеру файлы, нормализует имя для заголовка выдачи и проверяет права на каждом запросе. Обычная выдача возвращает исходные байты в режиме скачивания. Внутри текста выдаются только проверенные растровые изображения с того же origin. Прямой URL учитывает связку тенант, пространство, страница и публикация файла. Анонимный запрос, чужая страница и отозванное право получают `404` без имени и байтов.
- PostgreSQL хранит байты один раз и связывает их с черновиком, опубликованной страницей и редакциями. Повтор принятой загрузки или сохранения получает прежний результат. Под существующей блокировкой страницы проверяются версия, права, состояние файлов и лимиты. Публикация и история меняются одной транзакцией. Неиспользованные временные загрузки удаляются после срока черновика. История файлов начинается с первой публикации с вложениями. Снимки истории сохраняют файлы по тем же правилам хранения, что исторические обложки.
- Разработка и интеграционные проверки опираются на выпущенную [«Историю страницы 1.0»](kb-page-history-qa.md). Пакет включает загрузку и выдачу, вставку и удаление, а также интеграцию с восстановлением. Один фиксированный образ проверяется на отдельной копии базы и показывается на `4125`.

## Приёмка на одном кандидате

| Карточка | Обязательные проверки |
|---|---|
| KB-FIL-01 | До сохранения файл скрыт от второй сессии. После сохранения виден читателю после обновления. Проверить формат, пределы размера и количества, пустой файл, отказ в доступе, повтор, отмену, `409` и `503`. |
| KB-FIL-02 | Проверить исходные байты и имя с кириллицей, текущие права читающего админа, отзыв права, другой тенант, подстановку адреса с другой страницы и прямой адрес до публикации и после удаления. |
| KB-FIL-03 | Убрать файл с двумя вставками после подтверждения, сохранить другие файлы и Markdown, отменить действие, повторить сохранение, проверить исторический и удалённый текущий адрес. Восстановить редакцию со всеми файлами. |
| KB-FIL-04 | Выбрать существующий растр и загрузить новый. Проверить позицию, описание, декоративный режим, повторную вставку, Undo и переход в исходник. Сохранить, открыть в React и без JavaScript, проверить отзыв доступа. |

На сквозном показе редактор прикладывает файл, вставляет картинку, сохраняет страницу. Читатель обновляет её и скачивает файл. Редактор удаляет вложение с двумя вставками и восстанавливает его из прежней версии. Отдельно проходят регрессии Markdown, обложек и истории.
