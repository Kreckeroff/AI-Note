## Один сценарий на исходном экране

В «Документации команды» откройте «Доступ к пространству» и нажмите «Редактировать». Сохраняем шапку с организацией и пространством, дерево документов, центральную страницу, её заголовок и панель действий из этого прототипа. В панели слева идут «Заголовок», «Жирный», «Курсив», «Список» и «Код». Справа кнопка «Исходник» переключает это же поле между визуальным текстом и Markdown. Внизу остаются «Отменить» и «Сохранить». На узкой ширине переносим команды по правилам панелей исходного прототипа. Кнопка «Исходник» сохраняет видимое и доступное состояние нажатия.

Пользователь оформляет документ, переключается на исходник, вручную уточняет одну строку, возвращается к визуальной правке и сохраняет по прежнему адресу. Читатель увидит результат после обновления. Все шесть карточек входят в один пакет для реализации, проверки и показа на `4125`.

## Общий технический контракт

- React отвечает за визуальную правку и toolbar. У страницы один черновик исходника. Команды и ввод изменяют только затронутые диапазоны. Переключение представлений не запускает перезапись всего документа. При вводе проверяем выделение, положение курсора, вставку простого текста и составной ввод IME. Соседние строки, пробелы, маркеры и экранирование сохраняются. Неподдерживаемый блок занимает свой диапазон и остаётся доступен по команде «Исходник».
- Rust ведёт единый маршрут страницы и проверяет сессию, `Origin`, право и базовую ревизию перед записью. PostgreSQL хранит исходник и ревизию. Для прежних страниц сохраняем буквальное отображение и исходные байты при миграции. React и серверный HTML используют согласованный набор Markdown-элементов и общий набор примеров для проверки. HTML, введённый пользователем, отображается текстом. [Контракт исходника и совместимости](kb-md-02-start.md)
- При `503` остаются черновик, представление и базовая ревизия. При `409` рядом видны актуальная версия и черновик. Публикация совмещённого текста требует явного выбора основы и сохранения. Повтор уже применённого исходника не увеличивает ревизию. С первого доступного клика «Сохранить» показывает ожидание и блокирует повторную отправку.

## План общего среза

1. После согласования версии параллельно готовим серверное чтение, сохранение и совместимость прежних страниц, а также оболочку и визуальную механику исходного экрана. Используем один контракт черновика и фикстуры с исходником для обеих сторон.
2. Параллельно подключаем команды форматирования текста и команды для абзацев и списков к той же панели. Для каждой карточки проверяем ввод, переключение в исходник, сохранение и повторное чтение. Особое внимание уделяем позиции курсора и исходным символам вне правки.
3. На одном замороженном кандидате независимый QA прогоняет критерии карточек и сквозной сценарий с заголовком, смешанным выделением, списком, кодом и ручной правкой исходника. Сверяем старые страницы и права на копии базы. Проверяем Chrome на широком и узком экране, серверное чтение без JavaScript, ошибки, конфликт и ранний двойной клик. После проверки показываем весь пакет на `4125`.
