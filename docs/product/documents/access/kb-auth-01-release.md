# KB-AUTH-01 · Кандидат локального выпуска

[Критерии](kb-auth-01.md) · [Техническая спецификация](kb-auth-01-sa.md) · [План проверок](kb-auth-01-checks.md)

## Состав

Локальный веб-вход с заранее созданными аккаунтами и защищённым стартовым экраном. Сервер слушает только `127.0.0.1:4121`. Отдельная база SQLite хранит хеши паролей, сроки действия сессий и хеши их идентификаторов. Старт, создание аккаунта и поведение при ошибках описаны в [инструкции приложения](../../../../app/README.md).

Проверочный экземпляр использует временную отдельную базу и два тестовых аккаунта. Первый выпуск использует свою постоянную папку данных. Новая папка получает схему версии 1. База макета и реестр фич хранятся отдельно.

## Выпуск и возврат

1. После решения владельца остановить проверочный экземпляр на порту 4121 и запустить согласованный снимок с папкой данных установки.
2. Создать предвыданные аккаунты через CLI. Проверить вход владельца, обновление, отказ без сессии и одинаковую ошибку неверных данных.
3. При проблеме остановить процесс выпуска. Сохранить папку данных и журнал без экспорта паролей и cookie. Предыдущий пользовательский сценарий остаётся доступен в отдельном прототипе.

Публикация на внешнем адресе и изменение рабочих учётных записей не входят в этот кандидат.
