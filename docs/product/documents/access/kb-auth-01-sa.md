## Границы установки

Первая рабочая версия запускается локально на `127.0.0.1:4121`. Node.js и встроенный SQLite позволяют проверить вход с двумя постоянными аккаунтами на одном компьютере. CLI создаёт предвыданные аккаунты для установки. Графический интерфейс администратора, самостоятельная регистрация, выход, SSO и управление пространствами идут по отдельным карточкам. «Рабочая область» на этом шаге — защищённая стартовая страница с именем вошедшего пользователя.

## Контракт и данные

| Действие | Результат |
|---|---|
| `GET /` | Форма входа «Вход в аккаунт» с почтой и паролем |
| `POST /login` с корректными данными | Создаёт серверную сессию, выдаёт cookie и перенаправляет на `/workspace` |
| `POST /login` с неверными данными | Единое сообщение и одинаковый HTTP-ответ для неизвестной почты и неверного пароля. Почта остаётся в форме |
| `GET /workspace` | Имя аутентифицированного участника. Без действующей сессии выполняется переход на форму входа |

Аккаунт идентифицируется устойчивым ID, адрес нормализуется для входа, пароль хранится в виде стойкого хеша с индивидуальной солью. Сессия с непрозрачным случайным значением хранится на сервере, привязана к ID аккаунта и имеет срок действия. В SQLite хранится хеш значения сессии. Браузер хранит cookie с `HttpOnly` и `SameSite`. Сервер проверяет источник отправки, ограничивает попытки входа и ответы с данными сессии помечает как незакешируемые.

Локальный HTTP предназначен для доступа через loopback. Установка для общей сети потребует отдельной конфигурации HTTPS и проверки защиты сессий.
