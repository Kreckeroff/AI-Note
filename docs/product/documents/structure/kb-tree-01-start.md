# KB-TREE-01 · Пакет создания раздела

Редакция 1.0 · 18 ноября 2026 года · FC-018 · старт подтверждён

## Поведение

В «Документах» рядом с деревом доступна кнопка «Создать раздел». В пустом пространстве она также служит следующим действием. Открывается форма «Новый раздел» с полем «Название». Расположение задаёт открытое пространство. После создания раздел появляется в конце верхнего уровня дерева, становится выбранным и открывается с текстом «Этот раздел пока пуст».

[Существующий макет дерева и диалога](http://127.0.0.1:4120/design/sever-prototype/#doc/access) открывается на странице «Доступ к пространству». В дереве нажмите «Создать страницу или раздел», выберите «Раздел», укажите в расположении имя пространства и сохраните. [Хэндофф редактора](../../design/handoff/editor.md)

Владелец подтвердил, что создавать верхнеуровневый раздел могут владелец и назначенный редактор этого пространства. Администратор получает просмотр по роли тенанта и может создавать при отдельном назначении редактора или как владелец.

Правила первого среза

- Название обязательно, от 1 до 100 символов после удаления крайних пробелов. Названия на верхнем уровне пространства различаются после нормализации Unicode NFC и приведения регистра. При ошибке форма сохраняет ввод и показывает причину.
- Отмена возвращает в исходный экран «Документы» и восстанавливает фокус. После обновления страницы сохраняются порядок дерева и прямая ссылка на раздел.

## Технический контракт

- Строка раздела содержит UUID, тенант, пространство, автора, заголовок, ключ сравнения и порядок. Составной внешний ключ привязывает её к пространству того же тенанта. Миграция PostgreSQL добавляет таблицы разделов и операций создания. Сначала миграцию проверяем на отдельной копии базы.
- Канонический маршрут чтения `/workspace/{tenantId}/spaces/{spaceId}/sections/{sectionId}`. Глубокая ссылка проходит через существующий вход и проверяется заново после аутентификации. Единый ответ для отсутствующего и недоступного раздела сохраняет границу видимости. Состояние возврата в каталог учитывает текущий поиск, фильтр и страницу.
- `GET .../sections/new` открывает форму. `POST .../sections` применяет действующую проверку Origin, проверяет право записи и валидирует имя. Успешная запись возвращает `303` на раздел. Конфликт имени или идентификатора операции возвращает `409` с формой, неверное имя — `422`. Читатель получает `403` на действие записи, адрес вне доступного пространства — `404`.
- Запись и результат операции атомарны. Повтор с тем же идентификатором и названием возвращает ту же ссылку. Сервер назначает порядок внутри пространства так, чтобы параллельные создания сохранились обеими строками.
- React использует дерево и разрешения, полученные от Rust. Шапка продолжает показывать текущие тенант и пространство. Следующая карточка [KB-PAG-01](../pages/kb-pag-01.md) добавит действие создания страницы внутри раздела.

## Приёмка

| Проверка | Наблюдаемый результат |
|---|---|
| Владелец создаёт первый и второй раздел | Оба видны в порядке создания, выбран новый раздел, центральная область показывает пустое состояние. |
| Обновление и прямая ссылка | Тот же UUID и положение. Вход по прямой ссылке восстанавливает целевой раздел. |
| Роли и границы | Назначенный редактор создаёт раздел. Читатель и администратор с одним правом чтения видят раздел без действия записи. Чужой тенант получает нейтральный ответ. |
| Неверное имя, конфликт и параллельная запись | Форма показывает ошибку и исходный ввод. Точный повтор открывает ту же строку. Два одновременных создания разных разделов дают две строки с устойчивым порядком. |
| Диалог и клавиатура | Фокус на названии, Escape возвращает к прежнему экрану. На мобильной ширине поле, ошибка и действия доступны. |
| Совместимость с рабочими данными | На копии рабочей PostgreSQL после миграции проходят вход и открытие всех существующих пространств. Каталог и переключатель по-прежнему получают один набор. |
