## Что получит пользователь

При открытии пространства из каталога или переключателя открывается первая доступная страница в порядке дерева. Система выбирает первый раздел с доступной страницей, затем первую доступную страницу этого раздела. В центре открывается чтение, слева раскрыта ветвь и выделена выбранная страница. Этот порядок владелец подтвердил 18 ноября. [Хэндофф редактора](../../design/handoff/editor.md#вход-из-каталога-пространств)

Ссылка на конкретную страницу открывает именно её. При завершившейся сессии читатель сначала входит, затем продолжает по исходной цели. Сервер проверяет доступ заново. Если ссылка ведёт в другую доступную организацию, шапка показывает организацию и пространство страницы. Выбранная для обычного входа организация сохраняется. [Контракт входа из KB-SPC-02](../spaces/kb-spc-02-sa.md#http-и-навигация)

KB-PAG-01 уже присваивает странице постоянный UUID, открывает её после создания и поддерживает чтение по этому адресу. Сервер уже распознаёт прямую ссылку при входе и возвращает единый ответ для недоступной и неизвестной страницы. KB-PAG-02 подключает автоматический выбор при открытии пространства и проверяет весь маршрут получателя ссылки. В этой версии сохранённое содержимое страниц представляет пустой Markdown и отображается как «Пока здесь ничего нет.». Ввод и сохранение текста добавляет [KB-MD-01](../editor/kb-md-01.md).

## Состояния и макет

| Сценарий | Что видит читатель |
|---|---|
| В пространстве есть доступные страницы | Заголовок выбранной страницы, текущий раздел в пути, выделенную страницу в раскрытой ветви и содержимое в режиме чтения. |
| Разделы есть, в доступном дереве страниц пока нет | «Нет доступных страниц». Дерево доступных разделов открывается, явный переход к разделу показывает его содержимое и доступные действия. |
| Новое пространство без разделов | «В пространстве пока нет разделов». |
| Недоступная или неизвестная прямая ссылка | «Страница не найдена» и действие «К рабочей области». Заголовок и данные цели отсутствуют в HTML и модели React. |

## Технический контракт

- При `GET /workspace/{tenantId}/spaces/{spaceId}` сервер проверяет право чтения, выбирает первую страницу из разрешённого дерева и отвечает временным `303` на её канонический адрес. Поэтому в строке браузера сразу доступна ссылка на конкретную страницу. Если доступных страниц нет, сервер отвечает `200` с соответствующим пустым состоянием дерева по адресу пространства.
- Для выбора используется существующий порядок PostgreSQL по `sections.position`, затем `pages.position`. Доступ к дереву проверяет Rust по активному членству и действующему праву чтения пространства. Явные адреса раздела, страницы и форм продолжают выбирать свою цель независимо от первой страницы. React и серверный HTML получают один выбор и одно разрешённое дерево.
- Канонический `GET /workspace/{tenantId}/spaces/{spaceId}/pages/{pageId}` отвечает `200` только при доступе к указанной странице. Идентификатор раздела берётся из текущих данных, поэтому перемещение страницы в другой раздел того же пространства сохраняет её ссылку. При отсутствии действующей сессии используется локальный `returnTo`. Успешный вход возвращает `303` на очищенный адрес цели. Недоступность или отсутствие страницы после входа даёт нейтральный `404`.
- Переход и возврат в каталог переносят распознанные `q`, `scope` и `page`. Выбор страницы использует порядок дерева независимо от параметров каталога. Для временного ответа с перенаправлением применяется действующий `Cache-Control: no-store`, чтобы повторное открытие пространства заново проверило права и порядок. Временный сбой чтения отвечает `503`, повтор возможен на том же адресе.

Изменение укладывается в один срез чтения на существующих маршрутах, данных PostgreSQL и модели доступа KB-PAG-01.

## Критерии и проверки

| ID | Проверка на изолированной копии PostgreSQL | Наблюдаемый результат |
|---|---|---|
| К1 | Открыть пространство из каталога и переключателя. В тестовых данных первый раздел пустой, во втором несколько страниц, в третьем ещё одна. | Открывается первая страница по позициям разделов и страниц. Адрес содержит её UUID. Ветка выбрана в серверном HTML и React. Названия и даты не влияют на выбор. |
| К2 | Открыть ссылку на вторую страницу под другой учётной записью с просмотром. Повторить без сессии, ввести неверный пароль и затем войти верно. | При действующей сессии и после успешного входа открывается именно вторая страница. После обновления сохраняется её UUID, показывается текущее сохранённое состояние. Явная ссылка на раздел открывает раздел. |
| К3 | Запросить известную страницу без доступа, после отзыва доступа, под аккаунтом другого тенанта и с неизвестным UUID. | Во всех случаях после аутентификации одинаковый `404` для страницы. HTML и модель React не содержат название, путь по дереву и содержимое цели. |
| К4 | Открыть пространство без разделов и пространство, где есть только пустые разделы. | Оба состояния отвечают `200` и показывают соответствующий текст. Из состояния с разделами можно открыть раздел вручную. |
| К5 | Открыть пространство и прямую ссылку из другого доступного тенанта с поиском, фильтром и страницей каталога. Вернуться в каталог. | В URL страницы и переходе назад сохраняются распознанные параметры. Каталог и шапка относятся к тенанту ссылки. Выбор организации для следующего обычного входа сохраняется. |
| К6 | Проверить создание страницы, прежнюю прямую ссылку и временный сбой чтения на копии базы версии 3. | Создание ведёт на новую страницу, прежние ссылки снова открываются, временная ошибка допускает повтор запроса. |
