# Поставка микрофичи

1. Найди область в [карте контекстов](../../../product/contexts.md) и проверь каталог и доску на совпадения. Одна микрофича даёт один наблюдаемый результат для пользователя или оператора. Раздел продукта собирает связанные микрофичи. Фронтенд, API и хранилище относятся к одной микрофиче, когда реализуют её результат.
2. Заведи одну короткую историю со стабильным ID. Зафиксируй актора, цель, границы, основные исходы и критерии приёмки. Если история объединяет несколько независимо проверяемых действий, выдели отдельные карточки и свяжи предпосылки.
3. Подготовь нужные материалы по [шаблонам](../../microfeature-templates.md). Привяжи к ID макет с состояниями, техническую SA с контрактом и план проверки. Один спорный вопрос можно вынести в ad hoc и вернуть решение в карточку.
4. Пройди [согласования проекта](../../operating-model.md). После подтверждения старта реализуй поведение сквозь необходимые слои. Веди TDD небольшими срезами. Проверь критерии на рабочем продукте, включая права, сохранение, повтор и ошибки, если они затронуты.
5. Передай фиксированную версию независимому QA. Разбери и исправь подтверждённые ошибки, перепроверь новую версию и зафиксируй, как доказан пользовательский результат. Синхронизируй карточку, историю, результаты проверок и хэндофф. Выпуск проходит действующее согласование. Макет и отдельный технический слой служат промежуточными результатами.

При блокировке зафиксируй конкретное недостающее решение и продолжай доступные проверки внутри микрофичи. Подготовку независимых будущих карточек веди в бэклоге, пока текущий результат проходит приёмку.
