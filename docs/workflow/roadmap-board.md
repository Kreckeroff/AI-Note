# Требования к HTML-доске фич

Реализована первая локальная версия. [Запуск и работа с реестром](../../feature-center/README.md). В начальном реестре есть задачи по настройке процесса. Сроки, оценки и задачи будущего продукта добавляются при планировании.

## Назначение

Владелец и оркестратор видят, что запланировано, что требует согласования, что разрабатывается, что блокирует выпуск и почему. От карточки можно перейти к спецификации, макету, контракту, отчёту QA и релизу.

## Представления

1. **Реестр:** быстрый поиск по названию, описанию и ID; фильтры по этапу, обязательности, приоритету, владельцу, сроку и блокировке; сортировка по доступным полям.
2. **Рабочая доска:** этапы процесса, счётчики и карточки с чипами состояния. Переход карточки проверяет условия и требуемое согласование; простое перемещение не подделывает подтверждение владельца.
3. **Roadmap:** горизонты планирования, плановые и фактические даты, обязательные результаты и опциональные задачи. Возможность показать сегодняшний план определяется реальными датами/решениями; часовой пояс владельца — Europe/Moscow.
4. **Зависимости:** направленный граф блокирующих связей, обнаружение циклов, объяснение того, что задерживает задачу.
5. **Критический путь:** путь, определяющий срок завершения согласованного объёма по зависимостям и оценкам. Показывать расчётные допущения, дефицит оценок и влияние ограничений ресурсов.
6. **Карточка фичи:** проблема, поведение, критерии, связи, состояние согласований, артефакты, назначенные роли, история изменений и раунды QA.

## Независимые поля

| Поле | Значение |
|---|---|
| Обязательность | Must / Should / Could / отложено для текущего релиза |
| Приоритет | Очерёдность по решению владельца |
| Бизнес-критичность | Последствия отсутствия/задержки фичи |
| Состояние | Текущий этап, ожидание согласования, блокировка |
| Зависимости | Какая работа должна завершиться прежде |
| Оценка и доступная ёмкость | Основание календарного плана |
| Критический путь | Вычисленный признак для выбранного объёма и плана |
| Жёсткий срок | Ограничение с источником и владельцем решения |

Обязательная фича не всегда находится на расчётном критическом пути. Признак «важно» не заменяет расчёт пути. При неизвестных оценках граф остаётся графом зависимостей, а срок и критический путь отмечаются как нерассчитанные.

## Данные и сохранение

Предлагается начать с одного локального версионируемого реестра фич и связанных Markdown-документов. Окончательный формат выбирается перед реализацией. Для совместного использования возможен внешний трекер как источник статусов с явным адаптером.

Просмотр может быть статическим HTML. Изменение статусов, согласования и редактирование требуют механизма сохранения: локального сервиса либо согласованной записи/импорта данных. Хранение только в памяти страницы не обеспечивает сохранение. Browser localStorage годится для личных фильтров, но не заменяет общий реестр и аудит согласований.

Сохранять ревизию данных и автора изменения. Одновременные правки обнаруживаются по ревизии и требуют разрешения конфликта. Согласование привязывается к редакции артефактов. Недоступность синхронизации показывается явно, а не маскируется успешным изменением.

## Планирование

Оркестратор сначала защищает обязательный объём и жёсткие ограничения. Опциональные задачи назначает при свободной ёмкости и отсутствии влияния на согласованный срок обязательного объёма. Свободный слот агента — лишь один ресурс: учитываются зависимости, время владельца на согласование, окружения и проверки.

Кандидаты состояний: idea, discovery, requirements_review, design, design_review, technical_design, ready_for_implementation, implementation, qa, rework, ready_for_release, released, blocked. Точные названия и визуальное объединение колонок уточняются в дизайне. blocked дополнительно хранит причину и предыдущий этап.

## Проверяемые критерии первой версии

- Найденную через поиск фичу можно открыть вместе со всеми её артефактами и согласованиями.
- Фильтры и сортировки работают совместно; пустой результат объясняется и позволяет сбросить условия.
- На карточке различимы обязательность, приоритет, блокировка и фактический этап.
- Устаревшее согласование видно; старт/релиз при нём не выдаётся за разрешённый.
- Зависимости с циклом отмечаются как ошибка данных; календарный расчёт для них не выдумывается.
- Неизвестные оценки и даты остаются неизвестными; расчётный критический путь имеет доступное объяснение.
- Успешное изменение переживает перезагрузку и видно другому участнику при выбранном совместном режиме.
- Чипы различимы по тексту, элементы доступны с клавиатуры, состояние не кодируется только цветом.
