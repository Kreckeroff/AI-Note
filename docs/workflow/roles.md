# Роли агентов

Статус: предлагаемые карточки ролей. Это определения ответственности, а не зарегистрированные конфигурации runtime. Для текущего инструмента роль задаётся при фактическом запуске; навыки передаются явными ссылками. Набор доступных инструментов и жёсткие права определяются средой, а не названием роли.

## Общий контракт

На входе каждой роли: цель, версия фичи, утверждённые материалы, назначенные навыки, границы изменений, критерии готовности. На выходе: результат, пути/ссылки артефактов, выполненные проверки, неопределённости и следующий допустимый шаг. Передача между ролями идёт через оркестратора.

| Роль | Когда запускать | Результат | Предел ответственности |
|---|---|---|---|
| Оркестратор / продакт | Каждый новый запрос и переход | Маршрут, карточка фичи, пакет исполнителю, актуальные backlog/roadmap, журнал согласований | Согласования владельца остаются у владельца; переход основан на доказательствах готовности |
| Аналитик | Новое/неполное/изменённое поведение | Спецификация, сценарии, критерии приёмки, модель предметной области, вопросы | Факты проверяются по источникам; желания и решения подтверждает владелец |
| Архитектор | Значимые границы, интеграции, данные, сложность или техническая неизвестность | ADR, границы компонентов, публичные контракты, модель данных, план срезов и проверки | На подготовке исследует и проектирует; продуктовая реализация начинается после допуска |
| Дизайнер | Фича меняет пользовательский опыт | Версия макетов/прототипа, состояния, компоненты, дизайн-хэндофф | Самопроверка дизайна не заменяет согласование владельца |
| Фронтенд-разработчик | Согласован UI, контракт и старт | UI и состояние, поведенческие unit/component-тесты, интеграция, подтверждение критериев | Изменяет назначенную область; изменение контракта возвращает архитектору/аналитику |
| Бэкенд-разработчик | Согласован контракт, данные и старт | Доменная логика/API, постоянные тесты, миграции при необходимости, диагностика | Схему и внешние эффекты меняет по утверждённому плану |
| Инженер тестирования | Подготовка тест-плана, интеграция, системная регрессия | Матрица «критерий → проверка», интеграционные/контрактные/E2E-тесты, фикстуры и CI-команды | Unit/component-тесты остаются ответственностью автора реализации; специалист дополняет их |
| Независимый QA | Готов срез/кандидат либо поступило сообщение об ошибке | Новый отчёт с доказательствами, серьёзностью, покрытием и ограничениями | Чистый контекст; проверяет и воспроизводит; в режиме QA Bug Hunter пишет только разрешённые артефакты охоты |
| Проверяющий безопасность | Аутентификация, права, недоверенные данные, файлы, секреты, внешние эффекты либо отдельный запрос | Риски и воспроизводимые проблемы, проверки границ доверия | Действует в согласованном тестовом окружении; спорное ожидание возвращает владельцу контракта |
| Релиз-инженер | Кандидат прошёл допуск | Релизный пакет, результаты полного прогона, план отката, факт/итог выпуска | Выпуск выполняет в пределах отдельного подтверждения владельца |

## Выбор навыков

Для каждой задачи оркестратор выбирает основной метод работы, затем дополняет его навыками по поверхности изменения. Например, бэкенду нужны базовые правила реализации и TDD; миграция добавляет Migration Safety, а авторизация — Auth and Authorization. Навыки дизайна интерфейса не нагружают серверную задачу без соответствующей причины.

В [каталоге](skill-catalog.md) точные имена и файлы. При наличии одинаковых навыков из разных источников выбирается одна версия; зависимости и противоречия проверяются до запуска. Скилл предоставляет инструкции, плагин — возможности, роль — ответственность.

## Специальные назначения

- Архитектор до старта: Engineering Architecture/System Design, Domain Modeling и предметные архитектурные навыки. Arxitect Architect — исполняющий цикл реализации, а не нейтральный проектировщик; его условия остановки и принятия замечаний требуют приведения к проектному допуску.
- Аналитик: Grilling организует дерево решений. Факты среды исследуются агентом, решения владельца собираются небольшими раундами; численность раунда адаптируется к способу общения.
- Разработчики: TDD назначается с уже согласованными публичными границами тестирования. Повторно спрашивать подтверждённые границы не требуется.
- QA: независимый проход проверяет утверждённый контракт. Обнаружение багов и применение исправления — разные назначения; запрет изменения кода в QA Bug Hunter не переносится на разработчика.
- Diagnosing Bugs назначать разработчику: навык включает инструментирование, исправление и регрессию. Для независимого QA выбирать навыки воспроизведения и обзора, сохраняющие фиксированный снимок.
- Релиз: автоматические переходы, предусмотренные поставщиком инструмента, выполняются только в пределах выданного владельцем разрешения на выпуск.
